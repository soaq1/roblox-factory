# 첫 실행판 설계: 철 한 줄

- 작성: 2026-10-05
- 상태: 검토 대기
- 전체 설계: [게임 설계 문서](../game-design.md)

## 1. 목적

게임 설계 문서의 큰 틀 중에서 **가장 얇은 한 줄**을 실제로 돌아가게 만듭니다.

> 빈 섬에 블록을 놓고 부순다 → 추출기에서 철 원석이 나온다 → 벨트를 타고 굴러간다 → 석탄과 함께 제련로에 들어가 주괴가 된다 → 상자에 모인다 → 나갔다 들어와도 섬이 그대로다

이 실행판으로 확인하려는 것은 세 가지입니다.

1. **핵심 재미가 있는가.** 벨트 위로 물건이 굴러가고 기계를 거쳐 다른 물건이 되는 과정이 보고 있기에 즐거운가.
2. **물리 방식이 버티는가.** 굴러다니는 물체가 몇 개일 때부터 느려지는가.
3. **뼈대가 맞는가.** 블록 배치, 기계, 아이템, 저장의 구조가 이후 기능을 얹을 수 있는 모양인가.

완성도가 아니라 **답을 얻는 것**이 목표입니다. 겉모습은 임시이고, 설계 문서의 기능 대부분은 들어가지 않습니다.

## 2. 넣는 것

### 2.1 섬

- 접속하면 서버 안에 내 섬이 하나 생깁니다. 여러 명이 들어오면 서로 멀리 떨어진 자리에 각자의 섬이 생깁니다.
- 시작 섬은 흙과 돌로 된 작은 땅덩어리이고 윗면은 잔디입니다.
- 섬의 크기에 제한이 없습니다. 블록을 놓는 만큼 넓어집니다.

### 2.2 블록 놓기와 부수기

- 세계는 격자로 나뉘고 블록 하나가 격자 한 칸을 차지합니다. 한 칸의 크기는 3스터드입니다(원작과 같음).
- 화면 아래의 단축 칸에서 블록이나 기계를 고르고, 클릭해서 놓습니다. 놓기 전에 놓일 자리가 반투명하게 보입니다.
- 부수기 상태에서 클릭하면 부서지고 가방으로 돌아옵니다.
- 블록 종류: 잔디, 흙, 돌, 판자, 금속 바닥.
- 내 섬에서만, 캐릭터에게서 일정 거리 안에서만 놓고 부술 수 있습니다.

### 2.3 기계

기계도 격자 한 칸을 차지하고, 놓을 때 R 키로 방향을 돌립니다.

| 기계 | 동작 |
|---|---|
| 추출기 (철) | 몇 초마다 철 원석 하나를 출구 쪽으로 내보냅니다. |
| 추출기 (석탄) | 몇 초마다 석탄 하나를 출구 쪽으로 내보냅니다. |
| 직선 벨트 | 위에 닿은 물체를 앞으로 밀어냅니다. 플레이어도 실려 갑니다. |
| 코너 벨트 | 진행 방향을 90도 꺾습니다. 왼쪽용과 오른쪽용. |
| 합류기 | 두 줄을 한 줄로 합칩니다. |
| 제련로 | 입구로 들어온 석탄은 연료로 쌓고, 철 원석은 연료가 있을 때 몇 초에 걸쳐 주괴로 바꿔 출구로 내보냅니다. 연료가 없으면 원석이 안에 쌓인 채 멈춥니다. |
| 상자 | 입구로 들어온 물건을 담습니다. 클릭하면 안의 물건이 가방으로 옮겨집니다. |

추출기는 광맥 핵이 이미 꽂힌 상태로 주어집니다. 핵을 구해 꽂는 과정은 이번 범위가 아닙니다.

### 2.4 아이템

- 철 원석, 석탄, 철 주괴 세 가지입니다.
- 벨트 위와 바닥의 아이템은 **실제 물체**이고 로블록스 물리 엔진으로 움직입니다.
- 같은 종류의 아이템이 닿으면 하나의 묶음으로 합쳐집니다. 묶음에는 개수가 표시됩니다.
- 플레이어가 아이템에 닿으면 밀려납니다. 가까이서 E 키를 누르면 주워 가방에 넣습니다.

### 2.5 가방

- 아이템과 블록, 기계의 개수를 종류별로 가집니다.
- 화면 아래의 단축 칸 아홉 개와, 전체 목록을 보여 주는 가방 창이 있습니다.
- 이번 실행판에서는 조합이 없으므로, 처음 접속할 때 시험에 필요한 블록과 기계를 넉넉히 받습니다.

### 2.6 저장

- 섬의 블록과 기계, 기계 안의 상태(제련로의 연료와 원석, 상자의 내용물), 가방을 저장합니다.
- 일정 간격으로 자동 저장하고, 나갈 때 저장합니다.
- 다시 접속하면 그대로 복원됩니다.
- 바닥에 굴러다니던 아이템은 저장하지 않습니다.

### 2.7 측정 도구

물리 방식이 버티는지 재기 위한 개발용 기능입니다.

- 화면 구석에 서버의 초당 처리 횟수, 굴러다니는 물체 수를 표시합니다.
- 채팅 명령으로 추출기 속도를 임시로 몇 배 올릴 수 있습니다.

## 3. 넣지 않는 것

허브와 상인, 조합과 작업대, 광맥 핵 얻기, 몬스터와 전투, 전기, 플레이어 간 거래, 판매, 분쇄기를 비롯한 나머지 기계, 경험치와 레벨, 도감, 협동, 휴대폰 화면 맞춤, 소리.

**겉모습도 임시입니다.** 카탈로그의 모델은 이번에 넣지 않습니다. 기계는 로블록스 기본 도형을 조립해 색으로 구분하고, 입구는 노랑, 출구는 청록으로 표시합니다. 모델을 로블록스로 가져오는 과정은 따로 확인이 필요해서 다음 단계로 둡니다.

## 4. 구조

### 4.1 원칙

- **서버가 전부 결정합니다.** 클라이언트는 "여기에 이걸 놓고 싶다"고 요청만 하고, 서버가 거리, 소유, 빈자리, 가방의 개수를 확인한 뒤 실행합니다. 클라이언트가 보낸 값은 믿지 않습니다.
- **굴러다니는 아이템은 서버가 소유합니다.** 클라이언트가 아이템을 만들거나 옮길 수 없습니다.
- **정의와 동작을 나눕니다.** 블록, 아이템, 기계가 무엇인지는 표로 적어 두고, 동작하는 코드는 그 표를 읽습니다. 종류를 늘릴 때 표에 줄을 더하면 됩니다.
- **계산은 로블록스와 떼어 놓습니다.** 격자 계산, 가방 계산, 저장 형식 변환, 제련로의 판단은 로블록스 기능을 쓰지 않는 순수한 코드로 만들어, 스튜디오 없이도 자동 시험이 가능하게 합니다.

### 4.2 폴더

```
game/
  default.project.json     Rojo 설정
  src/
    shared/                서버와 클라이언트가 함께 쓰는 것
      Config               격자 크기, 속도 같은 수치
      Defs/                블록, 아이템, 기계 정의 표
      Grid                 격자 좌표와 방향 계산
      Inventory            가방 계산
      Codec                저장 형식 변환
      Net                  서버와 클라이언트 사이의 통신 통로 목록
    server/
      IslandService        섬 만들기, 섬별 블록과 기계 목록
      PlacementService     놓기와 부수기 요청 검증과 실행
      ItemService          굴러다니는 아이템 만들기, 합치기, 줍기, 정리
      MachineService       기계 등록과 주기적 동작
      machines/            추출기, 벨트, 합류기, 제련로, 상자
      SaveService          저장과 불러오기
      DebugService         측정 도구
    client/
      BuildController      놓일 자리 미리보기, 놓기와 부수기 입력
      HotbarUI             단축 칸과 가방 창
      DebugUI              측정값 표시
  tests/                   스튜디오 없이 도는 자동 시험
```

### 4.3 각 부분이 하는 일

| 부분 | 하는 일 | 기대는 곳 |
|---|---|---|
| Grid | 세계 좌표와 격자 칸 사이의 변환, 네 방향 회전, 이웃 칸 계산 | 없음 |
| Defs | 블록·아이템·기계의 이름, 색, 크기, 입출구 방향 | 없음 |
| Inventory | 개수 더하기와 빼기, 모자람 판정 | 없음 |
| Codec | 섬과 가방을 저장용 글자열로, 글자열을 다시 섬과 가방으로 | Grid, Defs |
| IslandService | 플레이어별 섬의 자리와 내용물 관리 | Grid, Defs |
| PlacementService | 요청 검증, 블록과 기계 만들고 없애기 | IslandService, Inventory, MachineService |
| ItemService | 아이템 물체 관리. 고유 번호 부여, 묶음 합치기, 상한 관리 | Defs |
| MachineService | 기계마다 정해진 간격으로 동작 호출 | ItemService |
| machines | 기계 종류별 동작 | ItemService, Defs |
| SaveService | 주기 저장, 나갈 때 저장, 들어올 때 복원 | Codec, IslandService |

### 4.4 기계와 아이템이 만나는 방식

- **벨트**는 고정된 판에 속도를 걸어 둔 것입니다. 닿은 물체가 그 방향으로 밀려 갑니다. 코드로 아이템을 옮기지 않습니다.
- **입구**는 보이지 않는 감지 구역입니다. 아이템이 닿으면 기계가 그 종류를 받을 수 있는지 확인하고, 받을 수 있으면 물체를 없애고 기계 안의 개수를 올립니다. 받을 수 없으면 그대로 둡니다.
- **출구**는 아이템이 새로 생기는 자리입니다. 출구 앞이 막혀 있으면 기계는 내보내기를 미룹니다.
- 물체 수가 정해 둔 상한을 넘으면 바닥에 오래 놓인 것부터 묶어서 정리합니다. 상한은 측정해서 정합니다.

### 4.5 저장 형식

- 블록은 종류별로 묶어서, 연속된 칸은 한 덩어리로 적습니다. 섬이 커져도 저장 크기가 천천히 늘게 하기 위해서입니다.
- 기계는 칸, 방향, 안의 상태를 적습니다.
- 형식에 판 번호를 넣어, 나중에 형식을 바꿔도 옛 저장을 읽을 수 있게 합니다.
- 스튜디오에서 게시하지 않은 상태로는 로블록스의 저장소를 쓸 수 없습니다. 그때는 서버가 켜져 있는 동안만 기억하는 임시 저장으로 대신하고, 화면에 임시 저장이라고 표시합니다.

**이번에 다루지 않는 위험**: 한 계정이 두 서버에 동시에 잡히는 경우의 잠금. 거래를 넣기 전에 반드시 넣어야 하지만, 혼자 시험하는 이번 실행판에서는 생기지 않습니다.

## 5. 잘못될 수 있는 것과 처리

| 상황 | 처리 |
|---|---|
| 이미 무언가 있는 칸에 놓으려 함 | 거절. 미리보기가 빨갛게 표시됨 |
| 가방에 없는 것을 놓으려 함 | 거절 |
| 남의 섬이나 너무 먼 곳에 놓으려 함 | 거절 |
| 요청을 너무 빠르게 보냄 | 초당 횟수를 넘는 요청은 버림 |
| 저장이 실패함 | 몇 번 다시 시도하고, 계속 실패하면 화면에 알림 |
| 불러온 저장이 깨져 있음 | 읽을 수 있는 부분만 복원하고 기록을 남김. 원본은 덮어쓰지 않음 |
| 기계 아래의 블록을 부숨 | 허용. 기계는 공중에 남음 |
| 아이템이 섬 밖으로 떨어짐 | 일정 높이 아래로 내려가면 없앰 |

## 6. 시험

- **자동 시험 (스튜디오 없이)**: Grid, Inventory, Codec, 제련로의 판단 규칙. 저장했다가 불러온 결과가 원래와 같은지, 방향을 네 번 돌리면 제자리인지 같은 것들을 확인합니다.
- **스튜디오에서 직접 확인**: 아래 순서를 따라 해 봅니다.
  1. 접속하면 섬이 생기고 그 위에 선다.
  2. 블록을 놓고 부순다. 가방의 개수가 맞게 변한다.
  3. 추출기 두 대, 벨트, 합류기, 제련로, 상자를 이어 놓는다.
  4. 철 원석과 석탄이 벨트를 타고 제련로로 들어가고 주괴가 나와 상자에 모인다.
  5. 석탄 쪽을 끊으면 제련로가 멈추고, 다시 이으면 돈다.
  6. 벨트 위에 올라서면 실려 간다. 아이템을 몸으로 밀 수 있다.
  7. 나갔다 들어오면 섬과 기계와 상자의 내용물이 그대로다.
- **측정**: 추출기 속도를 올려 가며 물체 수와 서버 처리 횟수를 기록합니다.

## 7. 필요한 도구

| 도구 | 쓰임 |
|---|---|
| 로블록스 스튜디오 | 게임을 열고 실행 |
| Rokit | 아래 도구들의 판을 맞춰 설치해 주는 관리 도구 |
| Rojo | 폴더의 코드를 스튜디오용 파일로 묶고, 스튜디오와 실시간으로 맞춤 |
| Lune | 스튜디오 없이 Luau 코드를 실행. 자동 시험용 |
| StyLua, Selene | 코드 모양 정리와 흔한 실수 검사 |

전부 무료이고 이 저장소 안에서만 쓰입니다.

## 8. 이 실행판이 끝나면 알게 되는 것

- 굴러다니는 물체가 몇 개까지 괜찮은지. 이 숫자가 공장의 규모와 묶음 규칙을 정합니다.
- 벨트의 속도, 추출기의 간격, 제련 시간이 어느 정도일 때 보기 좋은지.
- 블록 한 칸 3스터드가 캐릭터 크기와 맞는지.
- 다음에 넣을 것의 순서. 후보는 카탈로그 모델 가져오기, 조합과 작업대, 허브입니다.
