# 베타판: 카탈로그 전체를 놓아 보는 판

- 날짜: 2026-10-05
- 상태: 코드 작성 완료, **스튜디오에서 실행해 본 적 없음**
- 앞선 판: [첫 실행판 "철 한 줄"](2026-10-05-first-playable.md)

## 목적

카탈로그에 있는 것을 게임 안에서 전부 놓아 보고, 레시피 초안이 실제 공장으로 이어지는지 손으로 확인한다. 기본은 마인크래프트 크리에이티브처럼 무엇이든 무한히 꺼내 쓰는 방식이다. 여기에 더해 진짜 게임의 서버 쪽 규칙(실제 가방, 조합, 작업대 단계, 돈, 거래)이 들어 있고, 화면은 아직 없어서 채팅 명령으로 써 본다. 허브, 상인, 몬스터, 전기는 아직 없다.

## 들어간 것

| 항목 | 내용 |
|---|---|
| 블록 | 34종 전부. 옆면 색에, 윗면 색이 다른 블록(잔디, 통나무, 경작지 등)은 윗면에 얇은 덮개 |
| 기계의 겉모습 | 카탈로그 모델 84개를 로블록스 기본 도형(상자, 원기둥, 공)의 조합으로 자동 변환. 스튜디오로 모델 파일을 가져오는 과정이 필요 없음 |
| 동작하는 기계 | 37종. 아래 표 |
| 모양만 있는 기계 | 나머지. 목록에 "모양만"이라고 표시됨. 놓고 부술 수 있음 |
| 큰 기계 | 2×1, 2×2, 3×3칸짜리는 그만큼 칸을 차지함. 키가 큰 기계는 위 칸도 차지함 |
| 심는 것 | 묘목(잔디나 흙 위, 45초 뒤 나무가 됨), 밀 씨앗(경작지 위, 60초에 걸쳐 3단계로 자람. 부수면 밀과 씨앗) |
| 아이템 | 108종 전부를 목록의 "아이템" 탭에서 골라 바닥에 떨어뜨릴 수 있음(한 번에 8개). 기계에 무엇이든 먹여 보기 위한 시험 기능 |
| 목록 화면 | 블록 / 기계 / 아이템 탭, 왼쪽에 분류, 오른쪽에 그림. 기계는 실제 모델이 그림으로 보임 |

### 동작하는 기계

| 종류 | 기계 | 동작 |
|---|---|---|
| 벨트 | 벨트, 코너 벨트(오른쪽, 왼쪽), 열린 벨트 | 닿은 것을 물리로 실어 나름 |
| 내보내기 | 추출기(철, 석탄, 구리), 물 펌프, 펌프잭 | 2초마다 하나씩 내보냄. 출구가 막히면 기다림 |
| 가공 | 제련로, 분쇄기, 세척기, 체, 프레스, 선반, 인발기, 주조기, 제재기, 가마, 고로, 합금로, 혼합기, 제분기, 오븐, 착유기, 정유기, 직조기, 석재 절단기, 보석 세공기, 연탄기 | `docs/recipes.md`의 "가공" 표 그대로. 재료가 모이면 정해진 시간 뒤 결과물을 내보냄. 불을 쓰는 기계는 연료(통나무, 숯, 석탄 등)도 받아야 함 |
| 넘기기 | 분배기, 합류기, 깔때기, 자석 선별기 | 받은 것을 그대로 넘김. 분배기는 출구를 번갈아, 자석 선별기는 철 계열만 둘째 출구로 |
| 보관 | 보관함 | 들어온 것을 모음. F로 가방에 꺼냄 |

가공 기계는 레시피 표를 읽어 동작하므로, `data/recipes.py`에 가공 레시피를 더하고 `python3 data/recipes.py`와 `python3 game/tools/gen_data.py`를 실행하면 코드 수정 없이 게임에 반영된다.

### 기계끼리 붙여 놓았을 때

출구 바로 앞에 다른 기계가 붙어 있으면 물건을 떨어뜨릴 자리가 없다. 이때는 그 기계의 입구가 이쪽을 향하고 있으면 벨트 없이 바로 넘겨주고, 아니면 막힌 것으로 보고 기다린다.

## 진짜 게임의 서버 규칙

전부 서버에서 판단한다. 화면 쪽은 요청만 보내고, 서버는 요청마다 종류, 개수, 거리, 빈도를 확인한다.

| 항목 | 내용 |
|---|---|
| 두 가지 모드 | 크리에이티브(기본): 무엇이든 무한. 생존: 가방에 있는 것만 놓을 수 있고, 부수면 가방으로 돌아옴. 채팅 `/mode survival`, `/mode creative`로 바꿈. 이 전환은 시험용이며 출시 전에 없앤다 |
| 가방 | 아이템, 기계, 블록을 모두 담음. 블록을 부수면: 통나무와 돌처럼 아이템이기도 한 블록은 그 아이템으로, 흙은 흙덩이로, 나뭇잎은 10% 확률로 묘목이, 나머지는 블록 그대로 |
| 조합 | `docs/recipes.md`의 조합 141종 그대로. 가방 조합은 어디서나, 나머지는 해당 작업대에서 15스터드 안에 있어야 함. 재료가 하나라도 모자라면 아무것도 쓰지 않음 |
| 작업대 단계 | 일곱 작업대가 1~3단계. 단계는 놓인 작업대 하나가 아니라 섬에 붙어서, 작업대를 옮겨도 사라지지 않음. 통합 작업대는 일곱 작업대 3단계를 대신함 |
| 손 작업 | 기계가 하는 가공을 손으로. 해당 자리(손 화덕, 부품 작업대 등) 가까이에서, 필요한 도구(망치, 양동이)가 가방에 있어야 함. 불을 쓰는 작업은 가방의 연료를 약한 것부터 태우고, 남은 열은 다음 작업에 이어 씀 |
| 추출기 | 빈 추출기 + 광맥 핵을 가방에서 조합하면 그 광물의 추출기가 됨 |
| 돈 | 시작 10,000코인(임시 값). 지금은 거래에서만 오감. 상인과 가격표는 없음 |
| 거래 | 한 사람이 청하고 상대가 마주 청하면 열림. 각자 물건과 코인을 올리고 둘 다 준비되면 한꺼번에 교환. **누가 올린 것을 바꾸면 양쪽 준비가 모두 풀림**(원작의 사기 수법 방지). 교환 직전에 양쪽이 올린 것을 아직 갖고 있는지 다시 확인 |
| 저장 | 가방, 코인, 작업대 단계, 모드가 섬과 함께 저장됨 |

### 채팅 명령

물건 이름은 영어 이름(`ingot_fe`, `block:planks`)이나 띄어쓰기를 뺀 한글 이름(`철주괴`)으로 쓴다.

| 명령 | 동작 |
|---|---|
| `/mode survival` · `/mode creative` | 모드 전환 |
| `/give 철주괴 50` | 가방에 넣기. 크리에이티브에서만 |
| `/can` | 지금 서 있는 자리에서 가진 것으로 만들 수 있는 것 목록 |
| `/craft 기본작업대` · `/craft 벨트 3` | 조합. 숫자는 횟수 |
| `/hand 철주괴 4` | 손 작업 |
| `/upgrade 기본작업대` | 작업대 단계 올리기 |
| `/trade 이름` | 거래 청하기, 또는 청해 온 거래 받기 |
| `/offer 철주괴 10` · `/coins 500` | 거래에 올리기. 0이면 내림 |
| `/ready` · `/unready` · `/cancel` | 준비, 준비 취소, 거래 취소 |

### 아직 비어 있는 것

- **가격표와 파는 구조**: 개발자가 직접 설계하기로 해서 넣지 않았다. 코인을 벌거나 쓰는 곳이 거래 말고는 없다.
- 조합, 거래, 가방의 화면. 지금은 채팅 명령과 화면 위 알림 글자로만 보인다.
- 도구의 효과(곡괭이 등급에 따른 속도). 부수기는 지금 즉시 된다.
- 손 작업에 걸리는 시간. 지금은 즉시 된다.
- 거래 도중 서버가 꺼졌을 때의 처리. 두 사람의 저장이 따로 이뤄지므로 한쪽만 저장될 수 있다. 출시 전에 다뤄야 한다.

## 넣지 않은 것

상인과 가격, 허브와 포탈, 몬스터, 광맥 핵이 광산에서 나오는 것, 전기, 조립기처럼 레시피를 골라야 하는 기계, 감지기 같은 판단 장치, 승강기 같은 물리 장치, 자판기.

카탈로그의 "판매기"는 섬에 판매기를 두지 않기로 한 결정에 따라 게임 목록에서 뺐다.

## 구조

```
art/factorykit.py -- gamedata   →  game/tools/modeldata.json   (모델을 이루는 기본 도형 목록)
art/blocks.py                   →  art/catalog/blocks.json     (블록 색)
data/recipes.py                 →  data/recipes.json           (레시피)
                 game/tools/gen_data.py
                          ↓
game/src/shared/Defs.luau, Recipes.luau, ModelPalette.luau, Models/*.luau   (자동 생성, 손으로 고치지 않음)
```

- `shared/ProcessLogic.luau`: 가공 기계의 판단(받기, 연료, 진행, 내보내기). 시험 있음.
- `shared/Grid.luau`: 여러 칸짜리 기계가 차지하는 칸 계산. 시험 있음.
- `shared/ModelBuilder.luau`: 도형 목록으로 겉모습을 만듦. 서버(놓인 기계)와 클라이언트(목록 그림)가 같이 씀.
- `server/machines/`: 동작 종류마다 파일 하나(Belt, Extractor, Processor, Passthrough, Chest, Plant, Decor).
- `server/Outlet.luau`: 물건을 출구 밖에 떨어뜨리거나 붙어 있는 기계에 넘김.
- `shared/CraftLogic.luau`(조합, 손 작업, 작업대 단계), `shared/TradeLogic.luau`(거래), `shared/Wallet.luau`(코인), `shared/Stock.luau`(가방에 담기는 것과 블록·기계 사이의 변환). 모두 시험 있음.
- `server/CraftService.luau`, `TradeService.luau`, `Profile.luau`(가방·코인·단계·모드를 화면에 알리고 저장에서 읽음), `Commands.luau`와 `GameCommands.luau`(채팅 명령), `RateLimit.luau`(요청 빈도 제한).

## 확인한 것과 못 한 것

확인함: 계산 부분의 자동 시험 68개(거래에서 물건이나 코인이 생기거나 사라지지 않는지를 무작위 300회로 확인하는 것 포함), 문법과 타입 검사, 흔한 실수 검사, 게임 파일 빌드, 모델 자료의 수치 검사(회전값이 올바른지), 다른 Claude의 코드 검토.

**확인 못 함**: 스튜디오에서의 실행 전부. 특히

1. 기본 도형으로 바꾼 모델이 카탈로그 그림과 얼마나 비슷해 보이는지. 비스듬한 면과 톱니는 단순한 상자와 원기둥이 되므로 덜 정교하다.
2. 기계 입구가 벨트 끝의 물건을 제대로 받는지, 출구에서 나온 물건이 다음 벨트에 얹히는지.
3. 목록 화면의 기계 그림이 제대로 보이는지.
4. 기계가 많을 때의 속도. 기계 하나가 도형 평균 36개, 가장 많은 것(무한 동력로)이 149개다.

## 스튜디오에서 해 볼 것

1. 실행해서 섬에 서 있는지 확인. 출력 창에 빨간 글씨가 있으면 그대로 전달.
2. E를 눌러 목록 확인. 기계 탭에서 그림이 보이는지.
3. 철 추출기 → 벨트 → 제련로 → 벨트 → 보관함. 석탄 추출기를 코너 벨트로 제련로 앞 벨트에 합류.
4. 제련로 뒤에 프레스를 벨트 없이 바로 붙여 보기(철판이 나와야 함).
5. 아이템 탭에서 통나무를 골라 제재기 입구 앞 벨트에 떨어뜨리기(판자와 톱밥).
6. 묘목을 잔디에 심고 45초 기다리기. `/speed 10`을 치면 빨라짐.
7. 생존 모드 써 보기. `/give 판자 8` → `/mode survival` → `/craft 기본작업대` → 기본 작업대를 놓고(가방에서 하나 줄어야 함) 부수기(다시 늘어야 함). 땅의 돌을 부수면 가방에 돌이 들어오는지.
8. 2×2칸짜리(제조 공장)와 3×3칸짜리(핵 제련소)를 놓아 보기. R로 방향을 바꿔 가며 초록 윤곽과 실제로 놓인 자리가 맞는지 확인. 이 둘은 아직 모양만 있음.
